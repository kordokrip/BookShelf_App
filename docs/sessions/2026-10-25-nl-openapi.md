## 구현
| 기능 | 내용 | 파일 |
|---|---|---|
| 장르·쪽수 | 장르의 KDC 근거를 **소장자료 classNo → 서지정보 KDC → 부가기호** 순서로 고른다. KDC 매핑은 소수점 단위로 세분했다(004.73 AI, 005 프로그래밍, 911 한국사, 813.6~7 현대문학, 813.1~4 고전, 325.2 성공법 → AI 판단 등). 캐시 v3. 쪽수가 없으면 1일만 캐시. Open Library 대기 3초 | `lib/nlApi.ts`, `lib/kdcGenre.ts`, `lib/bookMeta.ts` |
| 저장 후 보정 | `POST /api/books`에서 장르가 `기타`이거나 쪽수가 비면 응답 뒤 백그라운드로 채운다. 둘러보기·AI 추천 '담기'가 이 모양으로 저장되던 경로였다. 그사이 사용자가 바꾼 값은 SQL 조건으로 보호한다 | `lib/bookMeta.ts` `fillMissingBookMeta`, `routes/books.ts` |
| 사서 추천 | 읽을 책 화면에 '사서 추천' 탭을 추가했다. 최근 12개월, 분야 칩(문학·인문·사회·자연), 소개 2줄, 담기. 표지는 User-Agent를 붙인 프록시로 받는다 | `lib/nlLibrarianPicks.ts`, `GET /api/discover/librarian`, `LibrarianPicksTab.tsx` |
| AI 요약 목차 | 서지정보에 목차 파일이 있으면 근거로 넣고 "목차 흐름에 맞추라"고 지시한다. 근거 안내에 '국립중앙도서관 목차'를 표시한다 | `lib/ai/bookSummary.ts`, `routes/ai.ts` |

## 실측 (로컬 실제 엔드포인트, 키 적용)
- **쪽수·장르(15권)**
  - 쪽수 12/15. 이전에는 Open Library만으로 3/15였다.
  - 장르 14/15. 틀린 1건은 총 균 쇠인데, 도서관 분류 389(문화인류학) → 사회과학이라 기준표 쪽이 옛것이다.
  - 11권은 KDC만으로 0.1~0.25초 만에 정해졌다(AI 호출 없음).
- **사서 추천**: 52권(12개월). 첫 응답 0.45초, 캐시 7ms. 표지 프록시 PNG 200.
- **저장 후 보정**: "핸즈온 머신러닝"을 장르 기타·쪽수 없이 담았더니 1초 안에 AI/데이터·488쪽으로 채워졌다.

## 측정 중 발견해 고친 것
- 부가기호 내용분류는 십 단위라서, 소장자료 classNo가 없으면 컴퓨터 책이 "000(총류)"이 된다. classNo를 주 근거로 바꿨다.
- 한국문학 시대 구분은 소수점 첫째 자리(813.62 → 6)인데, 처음 코드가 둘째 자리를 읽고 있었다.
- 사서추천 태그 이름은 문서와 다르다(`recomcontens`). 표지는 User-Agent가 없으면 403이다.
- 목차의 줄바꿈이 프롬프트 정리 과정(`sanitizeForPrompt`)에서 사라져 한 줄로 뭉개졌다.
- Open Library가 잠깐 응답하지 않은 결과(쪽수 null)가 30일 캐시로 굳었다. 쪽수가 없으면 1일만 캐시하도록 바꿨다.
