## 검증 중 발견해 고친 것
- **같은 날 같은 쪽수의 두 번째 독서 기록이 조용히 버려지던 버그**(출시 때부터, 운영 영향)

  - `datetime(created_at)`으로 맞춰 고쳤다. 관리자 통계의 6개월 조건도 같은 방식으로 고쳤다.
  - e2e TEST 73(11초 간격 두 번 기록 → 둘 다 반영)을 추가했다.
- **보안**
  - `scripts/admin-api-test.sh`에 실제 관리자 비밀번호가 기본값으로 커밋돼 있었다. 제거했고, 이제 환경 변수로만 받는다.
  - 스크립트가 만든 `nonadmin_` 계정도 끝나면 삭제하게 했다.
  - git 기록에는 남아 있으므로 **비밀번호 변경이 필요하다**.

  - 휴면 차단: 로그인·구글·토큰 갱신·`authMiddleware`(KV `user_dormant:{id}`)
  - 화면: 관리자 회원 목록 상태 필터·배지, 상세의 "계정 관리"

## 후속 (41차) — AI 컬렉션·인생책 개선
- **사용자 문제 제기**: 인생책은 새로고침해도 반응이 없고, 내 독서 데이터를 쓰는지 의심스럽다. 컬렉션을 AI가 만들어 시각화해 달라.
- **진단**(운영, 사용자 계정 완독 75권)
  - 인생책은 완독 전체를 프롬프트에 넣고, 이유에 실제 읽은 책(넥서스·파친코·츠바키 문구점 등)을 인용하고 있었다.
  - 새로고침도 6.9초 만에 새로 생성했지만 5권 중 4권이 같아 변화가 없어 보였다.
  - 24시간 캐시와 근거가 화면에 드러나지 않았다.
- **인생책 v2**
  - 추천마다 근거가 된 내 책을 반환한다(`based_on`, 서버가 내 책 제목과 대조해 검증).
  - 다시 고르기는 직전에 보여 준 책(최근 30권)을 빼고 고른다.
  - `basis`·`generated_at`을 추가하고 진행 상태를 표시한다.
  - 로컬 실측(12권): 싯다르타 ← 데미안, 작별하지 않는다 ← 소년이 온다처럼 근거가 정확히 나왔다.
- **AI 컬렉션**
  - `GET /api/ai/collections`(4~7개 묶음, 번호→책 id 매핑 검증, 한 책은 한 묶음)와 `POST /api/collections/from-books`(한 번에 생성)를 만들었다.
  - 컬렉션 화면에 비율 막대·카드·저장을 넣었다.
- **모델**
  - 기능별 모델 지정(`OPENROUTER_MODEL_CURATOR`)을 추가했다.
  - 유료 상위 모델(Claude Sonnet/Opus 5.5, Grok 4.7, GPT-5.5, Kimi K3, GLM 5.3)을 사용자 실데이터로 비교하려 했으나 **OpenRouter 계정 구매 크레딧이 $0**이라 402로 막혔다.
  - 현재 Gemini 3.8 Flash는 사용자 실데이터 인생책에서 3.3초, 6권 중 4권 사용 가능이었다.
  - 긴 응답(AI 컬렉션 2,500토큰)은 크레딧 충전 전까지 503(안내 표시)이다. 충전 후 비교해 상수 한 줄로 교체한다(`scripts/ai-bench/`).
