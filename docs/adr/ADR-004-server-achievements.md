# ADR-004: 업적을 서버 저장형으로 전환 + 캐릭터 진화
날짜: 2026-09-27 | 상태: 채택 | 결정자: 개발팀

## 컨텍스트
리뉴얼 Phase 3(북적북적의 캐릭터 수집 요소)은 "업적을 달성한 순간"에 축하와 캐릭터 진화를 보여줘야 한다. 그런데 기존 성취 배지(StatsPage `BADGES` 8종)는 통계 화면을 열 때마다 진행도로 다시 계산할 뿐, 달성 시점을 어디에도 기록하지 않았다. 그래서 "새로 달성했다"는 사건을 감지할 수 없었다.

## 결정
- **`user_achievements` 테이블(0016)에 달성 시각을 기록한다.** 한 번 달성한 업적은 진행도가 줄어도(책 삭제 등) 회수하지 않는다.
- **정의의 단일 원본은 서버다.** `worker/lib/achievements.ts`에 업적 8종(기존 id·임계치 그대로)과 캐릭터 2종(책 부엉이=완독 권수, 페이지 드래곤=읽은 페이지)을 둔다. 캐릭터 단계는 업적에 연결되어, 업적 달성이 곧 진화다.
- **평가 시점:** 진행도가 늘어나는 변경 API(완독으로 등록, 완독으로 전환, 세션 기록)가 끝난 뒤 평가한다. 새로 달성한 것이 있을 때만 응답에 `achievements: { newlyUnlocked, evolved }`를 붙인다(없으면 응답 형태 불변). 평가가 실패해도 원래 요청은 성공한다.
- **축하 폭주 방지:** "새로 달성"은 이번 행동 전후의 진행도를 비교해 **이번에 넘은 임계치만** 센다(`newlyCrossed`). 배포 전에 이미 넘은 업적은 조용히 소급 기록한다. 이렇게 하지 않으면 기존 사용자(예: 완독 75권)가 배포 후 첫 등록에서 업적 5개를 한꺼번에 축하받는다.
- **동시성:** `INSERT OR IGNORE`가 실제로 행을 추가한 업적만 보고해, 같은 업적이 두 요청에서 두 번 축하되지 않게 한다.
- **진행도 기준**은 `GET /api/stats`와 같다(완독 = `books.status='done'`, 페이지 = `reading_sessions.pages_read` 합).
- 화면(축하 모달, 캐릭터 카드)은 `characters` 플래그로 노출을 제어한다(ADR-003). 서버 평가·기록은 플래그와 무관하게 항상 동작한다. 그래야 공개 시점에 기록이 이미 준비되어 있다.

## 대안
- **클라이언트에서 이전 진행도를 localStorage에 저장해 비교:** 기기마다 따로 축하가 나고 기록이 사라질 수 있어 기각했다.
- **cron으로 일괄 평가:** "달성한 순간"의 축하가 불가능해 기각했다.

## 결과
- 오프라인 큐로 나중에 전송된 요청(`useOfflineQueue`)은 축하 모달 없이 기록만 된다(다음 조회 때 반영).
- 진행도 감소로 업적이 회수되지 않으므로, 책을 지웠다 다시 등록해도 같은 업적이 두 번 축하되지 않는다.
- 구현: `worker/lib/achievements.ts`(정의·순수 판정), `worker/lib/achievementsDb.ts`(D1), `worker/routes/achievements.ts`(`GET /api/achievements`)
