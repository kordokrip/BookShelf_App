# ADR-003: 리뉴얼 기능 공개 방식 — 기능 플래그 + 스테이징 점진 공개
날짜: 2026-09-27 | 상태: 채택 | 결정자: 개발팀

## 컨텍스트
북적북적·북모리 요소를 반영하는 리뉴얼(노트 v2, 책 쌓기, 캐릭터, 몰입 타이머, AI 태깅)은 여러 화면을 동시에 바꾼다. 지금까지는 `main` push가 곧바로 전체 사용자 공개였기 때문에, 새 UI를 실사용 데이터로 검증할 단계가 없었다. `wrangler.toml [env.staging]`은 이름과 vars만 있고 D1·KV·R2·AI·DO 바인딩이 없어 실제로는 동작하지 않는 상태다.

## 결정
- **기능 플래그(최소 구현):** `FEATURE_FLAGS` var(쉼표 구분)를 환경별 기본값으로 쓰고, `GET /api/flags`가 사용자에게 켜진 플래그를 돌려준다. 관리자(`role='admin'`)는 항상 전체 on이다. 프론트는 `useFlag(name)`으로 UI 노출만 분기한다.
- **API는 하위 호환 유지:** 새 컬럼·필드·엔드포인트는 추가만 한다. 서버에는 플래그 분기를 두지 않는다(플래그 off여도 API는 동작).
  - **예외 — `ai_tags`(2026-09-27, 전체 공개 후 제거):** 노트 AI 태깅은 공개 전까지 서버가 `userHasFlag()`로 확인했다. 플래그 없이 전 사용자 노트를 태깅하면 Workers AI 비용이 들고, 사용자에게 알리기 전에 노트 내용이 AI로 전송되기 때문이다. 비용·데이터 전송이 걸린 기능만 이 예외를 적용한다.
- **공개 순서:** 스테이징 전체 on → 프로덕션 관리자 계정만 on → 프로덕션 `[vars] FEATURE_FLAGS`에 추가해 전체 공개. 되돌릴 때는 var에서 빼고 배포한다.
- **스테이징 실동작화:** `[env.staging]`에 전용 D1·KV·R2 바인딩을 추가하고 `staging` 브랜치로 배포한다(2026-09-27 리소스 생성·바인딩 완료, 절차는 `docs/CI_CD.md`).

## 대안
- 외부 플래그 서비스·KV 동적 플래그: 사용자 수와 규모에 비해 과하고, 운영 포인트가 늘어 기각했다. 필요해지면 `resolveFeatureFlags()`만 교체하면 된다.
- 장기 feature 브랜치: `main`과의 드리프트와 대규모 머지 리스크가 있어 기각했다.

## 결과
- 새 UI를 프로덕션 데이터로 관리자가 먼저 검증할 수 있다.
- 플래그 제거(전체 공개 후 분기 코드 정리)는 기능별 후속 커밋으로 처리해야 한다. 방치하면 죽은 분기가 쌓인다.
- **2026-09-27 전체 공개:** 5종(`notes_v2`, `book_stack`, `characters`, `focus_timer`, `ai_tags`) 모두 프로덕션 `[vars]`에 추가했다. 스테이징·관리자 검증과 WebKit·Chromium 기기 에뮬레이션 점검 후 진행. AI 태깅 비용은 사용자당 하루 한도(`worker/lib/ai/noteTagger.ts`의 `DAILY_TAG_QUOTA`)와 KV 캐시로 묶여 있다. 분기 코드 정리는 아직 하지 않았다 — 공개 후 한동안 문제가 없으면 기능별로 제거한다.
- **2026-09-27 분기 제거:** 전체 공개 직후 사용자 요청으로 5종의 플래그 분기(`useFlag` 분기, 옛 타이머 위젯·화면 계산 배지·서식 미적용 렌더링·온보딩 3장 버전, 서버 `ai_tags` 확인)를 모두 제거하고 등록 목록 `ALL_FEATURE_FLAGS`를 비웠다. 되돌리기는 이제 플래그가 아니라 `git revert`로 한다. 플래그 장치(`/api/flags`, `useFlag`, `userHasFlag`)는 다음 단계 공개를 위해 남겨 둔다.
- 구현: `worker/lib/featureFlags.ts`, `worker/routes/flags.ts`, `src/hooks/useFeatureFlags.ts` — 등록된 플래그가 없어 지금은 호출하는 화면이 없다(다음 점진 공개용으로 남겨 둔 골격). 서버 단독 확인 `userHasFlag()`는 사용처가 없어 2026-10-10에 삭제했다(필요하면 git 이력에서 복원).
