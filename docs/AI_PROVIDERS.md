# AI 공급자·모델 운영 (현행 구성 + 결정 이력)

> AI 모델·공급자에 관한 결정과 측정을 한 곳에 모은 문서다(예전 세션 리포트 3개를 병합: 37차·42차·43차).
> 코드의 정확한 값은 `worker/lib/ai/llm.ts`·`worker/lib/ai/openrouter.ts` 상수가 기준이다.

## 현행 구성 (2026-10-11)

- **공급자 체인**(`worker/lib/ai/llm.ts`의 `generateText`)
  - 순서: Gemini 3.8 Flash(추론 `low`) → Gemini 3.5 Flash-Lite(`minimal`) → Workers AI `@cf/qwen/qwen3.8-27b`(thinking 끔) → OpenRouter 무료 목록(`models` 배열) → (요약·장르만) Workers AI 8B
  - 키 없음·일일 상한·404/429/5xx·타임아웃·빈 응답·형식 검증 실패면 다음 공급자로 넘어간다.
  - 1회 시도 상한은 Gemini 25초·Lite 20초(`attemptTimeout`)이다. Workers AI는 남은 시간이 예상 소요보다 짧으면 건너뛴다.
- **Gemini는 미국 위치의 중계 Durable Object(`GeminiProxy`, 위치 힌트 `wnam`)를 거친다.** Workers 데이터센터에서 직접 부르면 Google이 400 "User location is not supported"로 막는다.
- **키·시크릿**: `GEMINI_API_KEY`(Google AI Studio 무료 등급), `OPENROUTER_API_KEY`. 운영·스테이징 시크릿과 로컬 `.dev.vars`에 둔다. 무료 등급은 보낸 내용이 서비스 개선에 쓰일 수 있어 노트 본문은 보내지 않는다.
- **무료 한도**: Gemini 3.8 Flash는 분당 5회이고, 넘으면 Lite로 넘어간다. Workers AI는 하루 1만 뉴런(추천 1회 약 450), OpenRouter 무료는 계정 하루 50회다. 앱의 공급자별 일일 상한은 `LLM_DAILY_CAP`·`LLM_BACKGROUND_CAP`이다.
- **기능별 규칙**
  - 명문장은 Gemini만 쓴다(다른 모델은 문장을 지어냄). 성찰 질문은 체인 전체를 쓴다.
  - 추천은 카카오/네이버 실존 검증과 저자 교정, 즐겨 읽은 작가 보강, 판본·원서·잡지 제외, 책 조회 요청당 36회 상한을 적용한다.
  - 오늘의 회고 카드는 백그라운드로 만들고, 매일 KST 04시 Cron이 미리 만든다(`worker/lib/dailyCardService.ts`).
- **상태 확인**: 관리자 대시보드 'AI 공급자 상태'(`GET /api/admin/ai-status`) — 공급자별 마지막 성공·오류(오류 본문 앞부분 포함), 오늘 사용량.
- **다시 비교할 때**: `scripts/ai-bench/`(앱 프롬프트를 그대로 뽑아 비교).

## 결정 이력

### 2026-10-04 · 37차 — Gemma 3 27B → Gemini 3.8 Flash(유료, OpenRouter)

> 요청: "OpenRouter가 가격을 우선해 가장 느린 공급자로 가는 문제를 해결하도록, 빠른 응답을 받을 수 있는 모델을 찾아 적용". 현재 모델명은 `worker/lib/openrouter.ts`의 `OPENROUTER_MODEL`. 비교 스크립트는 `scripts/ai-bench/`.

### 배경
- 36차 실측에서 `google/gemma-3-27b-it`은 인생책 첫 생성이 13~42초로 들쭉날쭉했다.
  - 공급자 4곳의 속도 차이(초당 21~39토큰)가 컸다.
  - 처리량 우선 라우팅을 써도 꼬리 지연이 남았다.
- Workers 백그라운드(`waitUntil`)는 응답 뒤 약 30초에서 끊긴다. 그래서 느린 응답이면 '지난 추천' 갱신이 실패했다.

### 비교 방법
- 프롬프트는 앱 실제 코드에서 뽑았다(`buildLifeBookMessages`·`buildSummaryMessages`·`buildQuoteMessages`·`buildGenreMessages`).
  - 완독 12권 이력으로 인생책을 받는다.
  - 데미안 소개문으로 요약한다.
  - 데미안 명문장을 받는다.
  - '기타' 3권의 장르를 추천받는다.
- 요청 조건은 운영과 같다: JSON 모드, `provider.sort='throughput'`, 추론 모델은 추론을 끈 상태(`reasoning.effort` none/minimal).
- 인생책은 모델마다 3회 돌렸다. 후보 6권 중 '이미 읽은 책'과 '카카오 책 검색으로 실재가 확인되는 안 읽은 책(사용 가능)'을 셌다.

### 결정과 반영
- **모델**: `OPENROUTER_MODEL = 'google/gemini-3.8-flash'`, 추론은 `minimal`(`OPENROUTER_REASONING_EFFORT`). 처리량 우선 라우팅·JSON 지원 공급자 제한은 유지한다.
- **비용**: 호출당 인생책 약 $0.0017, 요약 약 $0.0006, 명문장·장르 약 $0.0004로 Gemma의 약 4배다. 일일 호출 상한(전체 1000회)에서 최악이어도 하루 약 $1.7 수준이다.
- **캐시**: 인생책 캐시 버전을 v5로 올려 Gemma가 만든 추천을 바로 새로 만들게 했다. 요약(7일)·명문장(하루)은 그대로 두어 자연스럽게 교체된다.
- **화면**: 제공 모델 표기를 "Gemini · OpenRouter", 추천 출처를 "AI 추천 · Gemini"로 바꿨다.
- **코드 주석**: 모델명 대신 'OpenRouter 모델'로 써서 다음 교체 때 고칠 곳을 줄였다.
- **유지되는 구조**: 실패 시 폴백(요약·추천 → Workers AI, 인생책·명문장 → 큐레이션·내 노트), 일일 예산, 22초 제한, 지난 추천 즉시 표시.

### 알려진 한계
- 비교는 하루 한 시점의 측정이다. 공급자 상태가 바뀌면 `scripts/ai-bench/`로 다시 비교한다(모델당 몇 센트).
- Gemini 3.8 Flash도 명문장을 기억으로 쓰므로 원문과 다를 수 있다. 카드의 안내 표시를 유지한다.

### 2026-10-05 · 42차 — 크레딧 $0 대응, 무료 Qwen 3.8 27B

> 요청: "OpenRouter 현재 남아 있는 무료 크레딧으로 쓸 수 있는 것을 정해서 설정". 현재 모델명은 `worker/lib/openrouter.ts`의 `OPENROUTER_MODEL`. 이전 유료 비교는 `docs/AI_PROVIDERS.md`.

### 배경
- 계정 상태(`GET /api/v1/key`, `GET /api/v1/credits`로 확인)
  - 구매 크레딧이 $0이라 유료 모델은 모두 402가 난다. 키 자체의 사용 한도($100)는 크레딧이 아니다.
  - 무료 모델은 `is_free_tier: true` 상태에서 **계정 전체 하루 50회**다. 남은 횟수는 응답의 `free_model_daily_requests`로 본다.
- 운영 영향: AI 컬렉션은 503, 인생책·추천 도서는 엄선 목록, 요약은 Workers AI 8B 폴백으로만 동작하고 있었다.

### 비교 (사용자 실데이터: 서재 76권)
요청 조건은 운영과 같다(인생책 6권·AI 컬렉션 프롬프트, 추론 끔).

| 모델 | 인생책 | AI 컬렉션 | 결과 |
|---|---|---|---|
| **qwen/qwen3.8-27b:free** (추론 none) | 7.7초, 6권(읽은 책 0, 근거 5/6 정확) | 12.6초, 6묶음, 76권 중 63권, 중복·잘못된 번호 0 | **채택** |
| google/gemma-4-31b-it:free, gemma-4-26b-a4b-it:free | 429 | 429 | 공용 풀 혼잡 |
| nvidia/nemotron-3-super·ultra:free | 12~74초 | 본문 없음 | 추론이 토큰 한도를 다 씀 |

Qwen 무료의 다른 작업(앱 프롬프트 그대로):
- 요약: 3.5초, 소개문 범위 안.
- 명문장: 0.9초. 원문과 가깝지만 맥락 설명이 틀릴 수 있다(카드의 안내 표시 유지).
- 장르: 0.6초.

인생책 품질은 Gemini보다 낮다. 저자가 틀린 책이 섞인다(예: 다른 저자 이름이 붙은 실존 책). 이런 책은 기존 실재 검증(카카오·네이버)에서 빠지고, 모자란 만큼 엄선 목록으로 채운다.

### 반영
- **모델**: `OPENROUTER_MODEL = 'qwen/qwen3.8-27b:free'`, 추론 `none`. 큐레이터(AI 컬렉션·인생책)도 같다. 유료로 되돌릴 모델은 `OPENROUTER_PAID_MODEL`(Gemini 3.8 Flash, 추론 `minimal`)로 남겼다.
- **JSON 모드**
  - Qwen 무료 공급자는 `response_format`이 없다. 보내면 404("No endpoints found that can handle the requested parameters")다.
  - `supportsJsonMode(model)`로 지원 모델에만 `response_format`·`require_parameters`를 보낸다.
  - 프롬프트가 'JSON만'을 요구하고 응답은 `extractJsonObject`로 꺼내므로 결과는 같다.
- **일일 예산**
  - 전체 `OPENROUTER_DAILY_BUDGET` 45회(계정 한도 50보다 작게), 오늘의 명문장 몫 `OPENROUTER_BACKGROUND_BUDGET` 15회로 낮췄다.
  - 예산을 넘기면 기존 폴백으로 넘어간다: 요약·추천은 Workers AI, 인생책은 엄선 목록, 명문장은 내 노트, AI 컬렉션은 안내 문구.
- **테스트**: JSON 모드 분기, 무료 예산 < 50.

### 알려진 한계
- 하루 50회는 **전 사용자 합산**이다. 캐시(요약 7일, 인생책·추천·컬렉션 24시간)로 버티지만 사용자가 늘면 오후에 폴백이 잦아진다.
- 무료 풀은 혼잡하면 429가 난다(배포 직후 측정에서 약 6번에 1번, 0.3초 만에 응답). 두 번까지 재시도한 뒤 폴백한다. 실패한 요청은 하루 횟수에 들어가지 않는 것으로 보인다.
- **크레딧 충전 후 되돌리는 법**
  - `OPENROUTER_MODEL`을 `OPENROUTER_PAID_MODEL`로 바꾼다.
  - `OPENROUTER_REASONING_EFFORT`를 `'minimal'`로 바꾼다.
  - 예산을 다시 올린다(전체 1000·백그라운드 600 수준).
  - 큐레이터용 상위 모델은 `scripts/ai-bench/`로 다시 비교한다.
- 크레딧을 $10 이상 구매하면 무료 모델 한도도 하루 1000회로 늘어난다(OpenRouter 정책, 바뀔 수 있음).

- 비교한 비Gemini 모델은 모두 명문장을 그럴듯하게 지어냈다(예: 같은 문장을 세 번 반복한 "고백"). **명문장은 Gemini만** 쓰고, 나머지 모델은 지어낼 위험이 없는 성찰 질문만 만든다.
- Gemini는 키 등록 후 같은 방법으로 비교한다(아래 '남은 일').

### 반영

#### AI 공급자 체인 (`worker/lib/ai/llm.ts`)
- **순서**
  1. Gemini
  2. Gemini Lite
  3. Workers AI Qwen 3.8 27B
  4. OpenRouter 무료 목록(`models` 배열)
  5. (요약·장르만) Workers AI 8B
- **다음 공급자로 넘기는 조건**: 키 없음·일일 상한·404·429·5xx·타임아웃·빈 응답·형식 검증 실패
- **시간**: 전체 마감 시간을 공유한다. Workers AI는 남은 시간이 예상 소요(토큰 ÷ 25/초)보다 짧으면 건너뛴다.
- **상한**: 공급자별 일일 상한과 백그라운드 상한을 둔다. 값은 `LLM_DAILY_CAP`·`LLM_BACKGROUND_CAP` 상수에서 확인한다.
- **조용한 고장 방지**
  - 공급자별 마지막 성공·오류를 KV `llm_status:{provider}`에 남긴다.
  - 관리자 대시보드 "AI 공급자 상태"(`GET /api/admin/ai-status`)에 표시한다. 이번처럼 모델이 사라지면 바로 보인다.

#### 근거 강화
- **저자 교정**: 제목이 정확히 맞고 저자만 틀린 후보를 실제 저자로 고쳐 쓴다. 전에는 버려서 6권 중 1~2권만 남았다.
- **보충 순서**: 후보 14권 → 즐겨 읽은 작가의 다른 책 → 엄선 목록
- **조회 상한**: 추천 1회의 책 조회를 36회로 제한한다(`RECOMMEND_LOOKUP_BUDGET`). Workers 무료 플랜의 요청당 외부 fetch 50회 안에 들게 하기 위함이다.

#### '당신을 위한 AI추천 도서'
- 인생책을 `GET /api/ai/recommend`로 통합했다.
  - 서재 전체를 근거로 하고 완독·별점에 가중치를 둔다.
  - 책마다 근거가 된 내 책을 붙인다.
  - 다시 고르기는 최근 40권을 제외한다.
- `/api/ai/lifebooks`와 `ai_life` 한도를 없앴다. AI 호출이 둘에서 하나로 줄었다.
- 화면
  - 탭 이름을 바꾸고 근거·다시 고르기·생성 시각을 넣었다.
  - `/lifebooks`는 리다이렉트한다.
  - 인생책 메뉴·링크와 읽을 책 배너를 삭제했다.

#### 오늘의 회고
- 날마다 **명문장**과 **성찰 질문**을 번갈아 보여 준다. 책은 별점 4~5점·최근 90일 완독에 가중치를 둔다.
- **명문장**: 문장·맥락·"왜 지금 울리는지" 한 줄. 고지 문구를 유지한다.
- **성찰 질문**: 도입·질문·[노트로 답하기]. 누르면 책 상세의 노트 시트가 "Q. 질문"으로 열린다.
- 책 소개(카카오/네이버)를 근거로 넣는다. Gemini를 못 쓰는 날은 성찰 질문만 만든다.

#### 기능 말풍선
- **대상**: 가입 7일 미만이면서 접속 7회 미만인 사용자
- **표시 방식**: 화면별로 하나씩 순서대로 보인다(14개). [알겠어요]·Esc로 닫으면 다시 안 보인다.
- **저장**: localStorage `bs_hints_seen`·`bs_visits`

#### 하단 메뉴
- 5칸이다: 완독·읽는 중·읽을 책·**컬렉션**·통계
- 컬렉션 아이콘은 `LibraryBig`이다. 서재 보기 줄의 폴더 아이콘은 삭제했다.

    - 작가 보강 이유의 을/를이 틀렸다.
    - 근거 라벨이 "좋아하셔서"였는데, 근거에 읽을 책이 섞이므로 "이 책들을 바탕으로"로 바꿨다.

### 남은 일 / 알려진 한계
- **Gemini 키 등록**(사용자)
  - 등록: `npx wrangler secret put GEMINI_API_KEY [--env staging]`
  - 등록 후 확인할 것:
    - 모델 id(`GEMINI_MODEL`·`GEMINI_LITE_MODEL`)
    - `reasoning_effort: 'minimal'` 허용 여부
    - 무료 한도에 맞춘 상한 조정
    - 실데이터 비교
  - 키가 없으면 첫 공급자가 Workers AI라서 추천 첫 생성이 30~60초 걸린다.
- **Workers AI 무료 1만 뉴런/일**: 추천 1회가 약 450뉴런이므로 하루 20회 남짓이다. 넘으면 OpenRouter 무료로 넘어간다.
- **Workers 플랜 미확인**: 요청당 외부 fetch 한도 50회를 가정해 조회 상한을 두었다.
- **Gemini 없이는 백그라운드 재생성이 거의 실패한다**
  - 지난 추천을 먼저 보여 준 뒤의 백그라운드 재생성 제한은 26초이고, Workers AI는 30~60초가 걸린다.
  - 서재가 바뀐 뒤에는 "지난 추천이에요"가 유지된다. [다시 고르기](동기 60초)로는 새로 받을 수 있다.
  - Gemini 키를 등록하면 2~3초라 해결된다.
- **남은 낮은 항목**
  - 말풍선이 Radix Tooltip 안에 버튼을 둔 구조라 키보드 Tab 접근이 멀다(Esc 닫기는 됨).
  - 로그인 화면은 모바일·데스크톱 폼이 함께 DOM에 있어 `id="login-email"`이 중복된다(기존).
  - 영문판(Cosmos ↔ 코스모스)은 제목 비교로 제외하지 못한다.
- **스테이징 QA 데이터**
  - subagent-user2에 책 9권과 노트 1개가 남아 있다.
  - QA 에이전트의 삭제가 권한 분류기에 막혀 정리하지 않았다. 사용자 판단이 필요하다.

### 후속 — Gemini 키 등록·실측 (같은 날)
- 키 등록: 사용자가 로컬 파일에 넣은 키를 운영·스테이징 시크릿(`wrangler secret put`, 파일 입력)과 `.dev.vars`에 등록했다. 값은 출력하지 않았다.
- 모델 id 확인(`GET /v1beta/models`): `gemini-3.8-flash`, `gemini-3.5-flash-lite` 모두 있다.
- **버그**: 직접 API는 3.8 Flash의 `reasoning_effort: 'minimal'`을 400으로 거절한다(OpenRouter 경유 때는 허용됐다). 그대로였다면 모든 호출이 Lite로 넘어갔다. 모델별 값을 따로 둔다: 3.8 Flash는 `low`, Lite는 `minimal`. 추론 여유 토큰은 600이다.
- **무료 한도**: 3.8 Flash는 분당 5회(`GenerateRequestsPerMinutePerProjectPerModel-FreeTier`)라 넘으면 429 → Lite로 넘어간다. 하루 한도는 AI Studio에서 확인한다.

|---|---|---|---|---|
| gemini-3.8-flash `low` | 9.6초 · 실존 11 + 저자 교정 1 · 없는 책 0 · 근거 11/12 | (분당 한도로 미측정) | 2.9초 | — |

- **명문장 한계**: 책 소개 없이 물으면 Gemini도 원문에 없는 문장을 만든다(예: 작별하지 않는다). 운영은 책 소개를 근거로 넣고 "원문과 다를 수 있어요" 고지를 유지한다.
- **운영 배포 후 문제 — 지역 제한**: 스테이징에서 Gemini가 모두 400이었다. 오류 본문을 상태 표시에 남기도록 고쳐서 확인했더니 "User location is not supported for the API use"였다. Workers가 외부로 요청을 보내는 데이터센터 위치를 Google이 막는다(로컬 PC는 정상).
  - 해결: Gemini 호출만 미국 위치 힌트(`wnam`)를 준 Durable Object(`GeminiProxy`)를 거치게 했다. 키는 중계 객체가 붙이므로 본 Worker 요청에는 실리지 않는다. 나머지 API는 그대로 가까운 곳에서 처리한다.
- **시도 시간 상한**: 해결 직후 스테이징에서 3.8 Flash가 오래 기다린 끝에 503("high demand")을 돌려줬고, Lite가 남은 시간 안에 끝나지 못해 엄선 목록으로 떨어졌다. 공급자 1회 시도에 상한을 두었다(Gemini 25초·Lite 20초, `attemptTimeout`).
- **작가 보강 보완**: 내 책의 다른 판본(넛지 → 넛지 기프트 에디션)과 한글 없는 원서 제목(Comet)을 뺀다.
- **운영 실측(사용자 서재 76권)**
  - 추천 도서: Gemini 11.3초, 10권이 모두 근거가 있는 추천이다(예: 하얼빈 ← 소년이 온다·파친코, 라플라스의 마녀 ← 미등록자·가면산장 살인사건).
  - AI 컬렉션: Gemini 9.0초, 6묶음에 55권을 분류했다.
  - 운영 e2e 76/76
